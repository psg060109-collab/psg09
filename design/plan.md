# 기획서 — 「불판 대첩」 (가제)

> 동아리 부스용 2인 대전 먹기 게임. PC 한 대, 키보드 하나를 둘이 나눠 쓰고, 한 판은 3~4분.
> 배포: GitHub Pages (정적 파일만, 서버 없음)

## 0. 한 줄 요약
가운데 식탁의 **공용 접시와 공용 불판**에서 음식을 먼저 집어 먹으며 **단백질·탄수화물·비타민** 세 수치를 지킨다.
**세 수치 중 하나라도 먼저 0이 되는 사람이 패배**한다. 수치는 시간이 갈수록 빨리 줄어들어 3~4분 안에 반드시 승부가 난다.

### 확정된 결정 사항
| 항목 | 결정 |
|---|---|
| 경쟁 방식 | 2인 대전, 한 화면 |
| 조작 | 키보드 하나를 좌우로 나눠 사용 (1P 왼쪽, 2P 오른쪽) |
| 식탁 | 접시·불판 **전부 공용** (상대가 구운 고기를 빼앗아 먹을 수 있음) |
| 수치 | 3종: 단백질 / 탄수화물 / 비타민 (최대 100) |
| 과식 | 100을 넘는 양은 버려짐 (페널티 없음) |
| 굽기 | 덜익음 → 익음 → 탐 |
| 종료 / 점수 | 먼저 0이 된 쪽이 패배하고, 버틴 시간이 기록이 된다 |

## ① 오브젝트 목록

### 음식 (접시 4종, 접시 하나에 한 종류)
| 키(1P/2P) | 음식 | 처리 | 굽는 시간 | 단백질 | 탄수화물 | 비타민 | 비고 |
|---|---|---|---|---|---|---|---|
| Q / U | 🍚 밥 | **바로 먹기** | – | 0 | +22 | 0 | 탄수화물의 주 공급원 |
| W / I | 🥩 고기 | 불판 | 6초 | +30 | 0 | 0 | 단백질의 유일한 대량 공급원 |
| E / O | 🍄 버섯 | 불판 | 4초 | +5 | 0 | +22 | 비타민의 주 공급원 |
| R / P | 🥬 상추 | **바로 먹기** | – | 0 | 0 | +10 | 비타민 응급용 (양이 적음) |

> 설계 의도: 바로 먹는 음식은 편하지만 양이 적거나 한 수치만 오른다. 많이 오르는 음식은 불판을 거쳐야 해서, 불판 칸이 늘 부족하다는 압박이 생긴다.

### 접시 (공용, 4개)
| 항목 | 값 |
|---|---|
| 접시당 최대 재고 | 3개 |
| 시작 재고 | 3개 |
| 보충 | 밥·상추는 2.5초, 고기는 3초, 버섯은 3초마다 1개씩 |
| 재고 0일 때 | 키를 눌러도 아무 일 없음 (접시가 흔들리는 피드백) |

### 불판 (공용, 4칸)
| 상태 | 조건 | 키를 눌렀을 때 |
|---|---|---|
| 빈칸 | – | 아무 일 없음 |
| 덜익음 🔴 | 올린 뒤 굽는 시간 전까지 | 아무 일 없음 (못 먹음) |
| 익음 🟢 | 굽는 시간 이후 4초 동안 | **누른 사람이 먹음** (먼저 누른 사람이 가져감) |
| 탐 ⚫ | 익음 상태가 4초 지나면 | **치우기** (영양 없음, 칸이 비워짐) |

- 불판 칸은 소유자가 없다. 누가 올렸든 익으면 먼저 누른 사람이 먹는다.
- 탄 음식은 누군가 치울 때까지 칸을 차지한다. 상대의 불판 자리를 막는 전략도 가능하다.
- 굽는 속도는 게임 내내 **일정**하다.

### 플레이어 (2명)
| 항목 | 값 |
|---|---|
| 시작 수치 | 각 수치 60 |
| 최대치 | 100 (넘는 양은 버려짐) |
| 먹기 쿨다운 | 0.35초 (키 연타 방지, 씹는 연출) |

## ② 수치(경제) 규칙

### 감소 속도 (모든 수치, 두 플레이어에게 동일)
```
감소량/초 = 1.2 + 0.012 × 경과초         (0초: 1.2/s, 120초: 2.6/s, 180초: 3.4/s)
210초 이후 추가 가속: + 0.05 × (경과초 − 210)  (240초: 5.4/s → 사실상 버틸 수 없음)
```
- 공급량은 일정한데 감소량은 계속 늘어나므로, **아무리 잘해도 약 4분 안에 누군가는 쓰러진다.**
- 아무것도 안 하면 약 40초 만에 0이 된다 (60 ÷ 평균 1.4/s). 부스에서 처음 해보는 사람도 금방 "먹어야 한다"를 깨닫는다.

### 종료와 기록
- 한 명의 수치 하나가 0이 되면 즉시 게임 종료, **상대가 승리**한다.
- 같은 틱에 둘 다 0이 되면 무승부.
- 결과 화면: 승자, 버틴 시간, 각자 먹은 음식 수.
- **부스 랭킹**: 가장 오래 이어진 대결 TOP 5를 브라우저(localStorage)에 저장해 대기 화면에 표시. 이름은 결과 화면에서 3글자 입력.

> 위 숫자는 시작값이다. 구현 후 headless 시뮬레이션으로 아래 목표에 맞을 때까지 조정한다.
> - 아무것도 안 하는 봇: 35~45초에 사망
> - 최적 플레이 봇 2명이 대결: **180~240초** 사이에 승부
> - 무작위로 키를 누르는 봇: 60초 안에 사망

## ③ AI 행동
대전 상대는 사람이라 적 AI는 **없다.**
대신 밸런스 검수용 **시뮬레이션 봇**(화면에 나오지 않음)을 둔다.
- `idle`: 아무것도 안 함
- `random`: 0.3초마다 8개 키 중 하나를 무작위로 누름
- `greedy`: 가장 낮은 수치를 올리는 행동을 우선하고, 익은 음식이 있으면 즉시 먹고, 탄 음식은 바로 치움

## ④ 조작 체계

```
1P (왼쪽)                    2P (오른쪽)
접시:  Q  W  E  R             U  I  O  P
       밥 고기 버섯 상추        밥 고기 버섯 상추
불판:  A  S  D  F             J  K  L  ;
       1  2  3  4번 칸         1  2  3  4번 칸 (같은 불판!)
```
- **접시 키**: 밥·상추는 즉시 먹기. 고기·버섯은 빈 불판 칸에 올리기.
  - 1P는 왼쪽 칸(1번)부터, 2P는 오른쪽 칸(4번)부터 빈칸을 찾는다.
  - 빈칸이 없으면 실패 (불판이 흔들림).
- **불판 키**: 익었으면 먹기, 탔으면 치우기, 덜 익었으면 무시.
- **Space**: 시작 / 다시 하기. **Esc**: 일시정지.
- 마우스는 쓰지 않는다 (이름 입력 제외).
- ⚠️ **키보드 고스팅**: 싼 키보드는 여러 키를 동시에 누르면 일부를 인식하지 못한다. 부스에서는 6키 이상 동시 입력이 되는 키보드를 쓰고, 행사 전에 시작 화면의 키 테스트 모드로 확인한다.
- `keydown`은 `event.code`로 처리해서 한/영 상태와 관계없이 동작하게 하고, 키를 꾹 누를 때의 반복 입력(`event.repeat`)은 무시한다.

## ⑤ 화면 구성 (가로 16:9, 1920×1080 기준으로 맞춰 축소)

```
┌──────────────────────────────────────────────────────────┐
│                       ⏱ 01:42                             │
│ [1P]                                              [2P]   │
│ 단백질 ██████░░             접시                ██████░░ │
│ 탄수화물 ████░░░░   [밥][고기][버섯][상추]     ████░░░░ │
│ 비타민 ███████░      Q·U  W·I  E·O  R·P          ███████░ │
│                                                          │
│                         불판                             │
│                 [ 1 ][ 2 ][ 3 ][ 4 ]                     │
│                  A·J  S·K  D·L  F·;                      │
│                                                          │
│  1P 키 안내                                   2P 키 안내 │
└──────────────────────────────────────────────────────────┘
```
- **수치 바**: 30 이하이면 노란색, 15 이하이면 빨간색으로 깜빡인다.
- **불판 칸**: 굽기 진행 링 표시. 덜익음은 붉은색, 익음은 초록색에 반짝임, 탐은 검은색에 연기.
- **접시**: 남은 개수를 점(●●○)으로 표시하고, 다음 보충까지 남은 시간을 얇은 바로 표시.
- **먹는 연출**: 먹은 쪽의 수치 바 옆에 `+22 탄` 숫자가 떠오른다 (관객도 누가 먹었는지 알 수 있게).
- **대기 화면**: 제목, 키 안내, TOP 5 랭킹, "Space로 시작". **3-2-1 카운트다운** 후 시작.
- **결과 화면**: 승자, 시간, 어떤 수치가 0이 되어 졌는지(예: "단백질 부족으로 패배!").

## ⑥ 완료 기준 (체크리스트)

### 핵심 규칙
- [ ] Space를 누르면 3-2-1 카운트다운 후 타이머가 0:00부터 올라간다
- [ ] 시간이 지나면 두 플레이어의 세 수치가 모두 같은 속도로 줄어든다
- [ ] 감소 속도는 0초보다 120초에서 더 빠르다 (공식대로)
- [ ] 1P가 Q를 누르면 밥 재고가 1 줄고 1P 탄수화물이 22 오른다 (최대 100)
- [ ] 2P가 U를 누르면 같은 밥 접시에서 재고가 줄고 2P 탄수화물이 오른다
- [ ] 접시 재고가 0이면 키를 눌러도 수치가 변하지 않는다
- [ ] 접시 재고는 정해진 간격마다 1씩 보충되고 3을 넘지 않는다
- [ ] W를 누르면 고기가 불판 1번 칸에, I를 누르면 4번 칸부터 올라간다
- [ ] 불판 4칸이 모두 차 있으면 고기·버섯 키를 눌러도 재고가 줄지 않는다
- [ ] 고기는 6초 전에 칸 키를 누르면 먹히지 않는다
- [ ] 6초 후 익음 상태에서 칸 키를 누른 플레이어의 단백질이 30 오르고 칸이 빈다
- [ ] 1P가 올린 고기를 2P가 먼저 눌러 먹을 수 있다
- [ ] 익은 지 4초가 지나면 탐 상태가 되고, 칸 키를 누르면 수치 변화 없이 칸이 빈다
- [ ] 먹기 쿨다운 0.35초 안에 같은 플레이어가 다시 먹을 수 없다
- [ ] 키를 꾹 누르고 있어도 한 번만 입력된다
- [ ] 한/영 상태와 관계없이 모든 키가 동작한다
- [ ] 한 플레이어의 수치 하나가 0이 되면 즉시 결과 화면이 뜨고 상대가 승자로 표시된다
- [ ] 결과 화면에 버틴 시간과 패배 원인 수치가 표시된다
- [ ] 결과 화면에서 Space를 누르면 모든 수치·접시·불판이 초기화된 새 판이 시작된다

### 밸런스 (headless 시뮬레이션)
- [ ] `idle` 봇은 35~45초 안에 사망한다
- [ ] `random` 봇은 60초 안에 사망한다
- [ ] `greedy` 봇끼리 대결하면 100판 평균 180~240초에 승부가 나고, 240초를 넘는 판이 5% 미만이다
- [ ] 270초를 넘는 판은 0판이다 (부스 회전율 보장)

### 부스 운영
- [ ] 대기 화면에 TOP 5 랭킹이 보이고, 새로고침해도 유지된다
- [ ] 키 테스트 모드에서 8개 키를 동시에 눌렀을 때 인식된 키가 화면에 표시된다
- [ ] GitHub Pages 주소로 접속하면 바로 실행된다 (빌드 없이)
- [ ] 브라우저 콘솔 에러 0건
- [ ] 1366×768 노트북 화면과 1920×1080 모니터 모두에서 잘리지 않는다

## 성능 상한
2D 게임이라 부담이 적지만, 상한은 미리 정해둔다.

| 항목 | 상한 | 지키는 법 |
|---|---|---|
| 목표 프레임 | 60fps (최악 장면에서 55 이상) | – |

## 기술 구성
- 순수 HTML + ES 모듈, 빌드 도구 없음. Three.js는 쓰지 않는다 (2D로 충분).
- 고정 타임스텝 로직(1/60초), 렌더링은 `requestAnimationFrame`.
- 로직과 렌더링을 분리해서 Node.js에서 headless 밸런스 시뮬레이션을 돌린다.
```
index.html
css/style.css
js/config.js     ← 모든 숫자(음식 영양값, 굽는 시간, 감소 공식, 보충 간격)
js/game.js       ← 순수 로직: 상태, update(dt), 행동(eat/place/take)
js/input.js      ← 키 매핑 → game 행동 호출
js/render.js     ← Canvas 그리기
js/main.js       ← 루프, 화면 전환(대기/카운트다운/게임/결과)
sim/simulate.mjs ← 봇 대결 headless 시뮬레이션
```

## 객관적으로 본 남은 위험 요소 (구현 후 확인)
1. **불판이 전부 공용이라 "구워주면 손해"일 수 있다.** 내가 올린 고기를 상대가 먹으면 손해라서 둘 다 안 굽고 버틸 수도 있다. 하지만 단백질은 고기로만 대량으로 오르니 결국 구워야 한다. 시뮬레이션과 실제 테스트에서 답답하게 느껴지면 → 올린 사람이 익은 직후 1초 동안 우선권을 갖게 바꾼다.
2. **불판 4칸이 둘에게 좁을 수 있다.** 테스트해 보고 답답하면 6칸으로 늘린다 (키는 그대로 두고 칸만 2배씩 묶는 방식은 혼란스러우니, 그때 키 배치를 다시 논의).
3. **키보드 고스팅**: 부스용 키보드를 미리 검사한다.
